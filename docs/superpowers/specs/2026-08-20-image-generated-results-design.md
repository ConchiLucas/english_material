# 图片生成结果归档设计

## 目标

在顶部“英语素材项目”展开菜单中增加“图片生成结果”，以批次为单位分页浏览图片工作台已经完成的最终成品。页面只回答“最终生成了什么”，不展示 Agent 中间输入输出、参考图、底图、Token、评分、失败批次或重绘操作。

## 产品方案

- 菜单顺序固定为“Agent 生成结果”“图片生成结果”。进入图片结果不会修改任何工作台草稿，离开存在未保存草稿的工作台时继续复用现有确认保护。
- 只查询状态为 `COMPLETED` 且至少有一张 `FINAL` 资产的图片批次，按批次创建时间倒序、ID 倒序分页。
- 默认每页 10 个批次，允许切换 20 或 100；换页和换每页数量均由服务端分页，不在浏览器一次加载全部历史。
- 每个批次占满内容区宽度。上层单行显示从故事快照提取的首个 Scene 标题、画风、最终分镜数、目标年级和完成时间；下层将最终图按 Scene/Shot 顺序放入响应式画廊。
- 每张卡片以图片为视觉主体，下方仅显示 `Scene N · Shot M` 和一行来源片段/对白/字幕摘要。点击图片打开大图预览，可在同一批次内前后切换。
- 图片加载失败时显示局部错误占位，不影响同批次其他图片；批次页读取失败保留当前页并允许重试；初次失败、空数据分别显示独立状态。

## 后端设计

新增 `GET /api/image-runs/results?page=1&pageSize=10`：

- 参数约束为页码从 1 开始，每页数量只能是 10、20、100。
- 第一条分页查询只选择满足条件的 `ImageRun`，避免对全部历史做内存分页。
- 第二组有界批量查询以当前页 runId 集合读取 `FINAL` 资产和对应分镜，不产生逐批次 N+1 查询。
- 返回 `ImageResultPage`，每个 `ImageResultItem` 包含批次元信息和最多 20 个 `ImageResultShot`。图片只暴露资产 ID，不返回 MinIO Bucket、对象键、Endpoint 或凭据。
- 服务端按分镜 sequence 排序，并要求 FINAL 资产能与同 runId 的 shotKey 对应；异常或孤立资产不进入结果。

## 前端设计

新增独立 `ImageGeneratedResultsPage`：

- 使用现有 Axios 实例请求结果页；所有图片 URL 只通过 `imageAssetUrl(assetId)` 构造，兼容绝对和相对 API Base。
- 使用 request generation 丢弃换页、换 pageSize 或卸载后的迟到响应。
- 页面保留旧数据进行分页加载；加载层仅降低画廊视觉权重，不清空当前图片。
- 使用 Ant Design `Image.PreviewGroup` 提供可访问的大图预览与同批次前后切换，不自行实现焦点陷阱。
- 样式全部使用 `.image-results-*` 前缀；桌面为自适应多列，窄屏单列，图片保持 16:9 且 `object-fit: cover`，内容容器不固定高度。

## 错误和安全边界

- React 只以文本节点展示标题、摘要和元数据，不渲染服务端 HTML。
- 后端分页及每批次最多 20 张图共同限制响应大小；前端不预取其他页。
- 资产读取继续经过 `/api/image-assets/{id}/content` 的哈希校验和 MIME 限制，页面不接收或使用后端 `contentUrl`。
- 无效页码或 pageSize 返回现有统一 API 错误；页数缩小时前端自动回退最后有效页。

## 测试

- 后端覆盖过滤、稳定排序、10/20/100 参数、批量组装、孤立资产忽略和无步骤查询。
- 前端覆盖默认分页、20/100 切换、完整批次画廊、受控资产 URL、预览、图片错误、分页失败保留、初始失败/空态、迟到响应和页数回退。
- App 覆盖展开菜单顺序、页面入口和故事/图片工作台未保存保护。
