# Agent 单列表与详情抽屉设计

## 目标

将 Agent 工作台收敛为单一列表页面。Agent 的配置编辑、在线测试和历史运行记录统一从列表操作列进入详情抽屉，减少并排区域和顶层视图切换造成的信息拥挤。

## 页面结构

主页面仅保留标题区、分类筛选、Agent 表格和“新增 Agent”按钮，不再展示左侧目录、中央编辑器、右侧测试面板、流程视图或全局运行记录页签。

表格列如下：

- 名称：展示 Agent 显示名称和 Agent Key。
- 职责分类：展示现有五类职责标签。
- 职责说明：单行省略，完整内容可在详情查看。
- 执行 CLI：展示当前统一生效的默认本地 CLI。
- 更新时间：展示 `UpdatedAt`，无值时显示占位符。
- 操作：提供“详情”按钮。

分类筛选继续使用现有分类定义。筛选结果为空时，在表格中展示空状态。

## 详情抽屉

点击“详情”从右侧打开宽抽屉；点击“新增 Agent”打开同一抽屉的空白新建态。抽屉关闭时保留列表位置，不改变当前分类筛选。

抽屉包含三个页签：

1. 配置编辑：包含身份、运行参数、提示词、质量约束以及输入输出 Schema。保存行为沿用现有新增和更新接口。
2. 在线测试：包含测试输入、运行按钮和本次测试结果。未保存的新 Agent、存在未保存更改或默认 CLI 不可用时禁止测试，并展示原因。
3. 运行记录：仅展示当前 Agent 的历史测试记录；新 Agent 在首次保存前展示引导空状态。

保存成功后保持抽屉打开并刷新列表数据。测试成功后将新结果加入当前 Agent 的记录中。关闭存在未保存更改的抽屉时弹出确认，避免误丢编辑内容。

## 数据与接口

沿用现有接口，不修改后端和数据库结构：

- `GET /api/agents`
- `POST /api/agents`
- `PUT /api/agents/{id}`
- `POST /api/agents/{id}/test`
- `GET /api/agents/runs`

页面加载时并行读取 Agent 和最近运行记录。详情中的历史记录在前端按 `agentId` 过滤。

## 组件边界

保留 `AgentWorkspacePage` 作为数据和交互状态容器，将表格列、详情抽屉内容和测试结果展示拆成清晰的渲染单元。此次只做与单列表布局直接相关的整理，不引入路由、删除能力、启停状态或后端分页。

## 响应式与可访问性

- 桌面端抽屉使用宽布局，保证 Schema 和提示词可编辑。
- 小屏设备抽屉占满可用宽度，表格允许横向滚动。
- “详情”“新增”“保存”“运行测试”均使用明确文本；抽屉和测试结果保留可访问名称及状态播报。
- 键盘关闭抽屉时同样触发未保存确认。

## 测试与验收

- 自动化测试验证主页面只呈现一个 Agent 表格，不再呈现顶层流程视图和运行记录页签。
- 自动化测试验证“详情”和“新增 Agent”会打开详情抽屉。
- 自动化测试验证运行记录只保留当前 Agent 的结果。
- 构建必须通过 TypeScript 与 Vite 校验。
- 浏览器验收覆盖桌面端列表、详情抽屉三个页签、新增态和窄屏布局。
