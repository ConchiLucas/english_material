# 图片故事工作台设计

## 目标

在一级“Agent 工作台”旁新增“图片工作台”，从已有故事批次的 `finalStory` 创建图片批次。第一版优先让用户逐个优化九个文本 Agent 的 Prompt，并以足够细的语义分镜保证故事覆盖；图片生成后交给用户人工审核。

成功结果必须同时满足：

- 输入只能来自已有故事运行记录，并在创建图片批次时保存故事快照。
- 每个 `Scene` 按动作、时间点和含义拆成 1—5 张图，整篇最多 20 张，不把 `Scene` 简化为固定一张图。
- 同一批次固定 16:9 横版和一个画风预设。
- 先生成角色设定图与主要场景设定图，后续分镜图都引用相关设定图。
- 同一角色的外貌、服装、比例、道具和场景规则跨图一致。
- 每个分镜只调用一次图片模型；第一版不做视觉评分、候选图比较、自动重绘或手工重绘。
- 图片模型只生成无字底图。对话由确定性程序排成角色气泡，叙事由确定性程序排成底部字幕。
- 用户能查看每个文本 Agent 的完整输入和原始输出，并编辑 Prompt、Provider、Temperature、启用状态和历史版本。

## 非目标

第一版不提供封面图、视频、音频、视觉评分 Agent、图像重绘、局部修复、候选图选择、拖拽编排、流程增删、跨重启续跑或分布式队列。用户审核只负责查看结果，不改变批次状态或触发后续调用。

## 已确认的产品选择

| 主题 | 选择 |
| --- | --- |
| 分镜粒度 | 每个 Scene 按语义动态拆分多个画面 |
| 连续性 | 连续绘本模式，角色、服装、道具、场景与画风跨图锁定 |
| 画风 | 创建批次时选择一个画风预设，整批锁定 |
| 自动化 | 分镜、提示词、参考图、分镜图与文字合成自动完成，最后人工审核 |
| 图片比例 | 16:9 横版 |
| 文字 | 对话气泡靠近说话角色；叙事字幕位于画面下方 |
| 文本改写 | 可压缩旁白并简化对话，但不能改变故事主线，保持三年级难度 |
| 图片数量 | 每 Scene 1—5 张，整篇最多 20 张 |
| 图片候选 | 每分镜一张，不生成候选图 |
| 参考资产 | 先生成角色设定图和主要场景设定图，并在详情中可见 |
| 图片模型 | 第一版固定一个支持多参考图的 Provider/模型 |
| 故事来源 | 只允许选择已有故事批次并保存 `finalStory` 快照 |

## 一级导航与页面

`web-react/src/App.tsx` 在“Agent 工作台”之后新增一级“图片工作台”。该页面不嵌入故事工作台，使用独立状态和未保存保护。

图片工作台包含三个配置页签：

1. **Agent 配置**：展示固定流程画布。点击九个文本 Agent 后，右侧内联编辑 Prompt、文本 Provider、Temperature、启用状态、变量、上下游、版本号和更新时间。
2. **画风预设**：新增、编辑、启用或停用预设。每个预设保存名称、正向风格约束、负向约束和示例说明；历史批次只读取自己的快照。
3. **图片模型**：从已启用且具备 `IMAGE_GENERATION` 与 `IMAGE_REFERENCE` 能力的 Provider 中选择唯一模型，并固定 16:9 输出参数。

页头提供：

- **开始生成**：选择一个 `finalStory` 非空的已有故事批次和一个已启用画风预设。确认页展示故事时间、目标年级、单词、故事预览、16:9、每 Scene 1—5 张和全篇 20 张上限。提交后立即创建异步图片批次。
- **图片记录**：打开全屏记录页。左侧选择批次，中间按实际顺序展示九个文本 Agent 及程序步骤，右侧展示所选步骤的完整输入与原始输出。下方以“参考设定图 / 最终分镜图”切换画廊，点击图片查看大图；分镜卡同时显示所属 Scene、镜头序号、来源故事片段、对白/字幕和最终图片提示词。

记录页不展示视觉评分、是否通过或重绘按钮。活动批次自动轮询，终态停止轮询。

## 固定多 Agent 流程

### 阶段一：故事理解与视觉约束

三个 Agent 可以并行读取同一故事快照和批次配置：

1. `image-story-analyst`（故事结构分析）：输出 Scene、情节节拍、动作、时间点、角色、道具、地点、原始对白和叙事文本。
2. `image-continuity-designer`（角色连续性）：输出角色与关键道具说明书，明确不可变外貌、服装、比例、颜色、表情范围和跨图连续性规则。
3. `image-art-director`（美术导演）：把选定预设扩展为色板、线条/材质、光线、景别、镜头语言、环境规则和禁止元素。

### 阶段二：双分镜提案与决策

4. `image-action-storyboarder`（动作分镜师）：按动作变化、视点变化和时间推进拆图，禁止单图描述互斥时间点。
5. `image-learning-storyboarder`（儿童叙事分镜师）：按三年级理解顺序拆图，并为每张图分配短对白或 1—2 句短旁白。

以上两个 Agent 可以并行，均读取阶段一输出。

6. `image-storyboard-director`（分镜总监）：合并两套提案，生成唯一分镜表。它必须验证每 Scene 1—5 张、整篇不超过 20 张、故事节拍全部覆盖、相邻镜头连续、每个镜头只有一个主要时间点，并为每张图分配稳定 `shotKey`。

### 阶段三：出图提示词准备

7. `image-reference-planner`（参考资产规划）：根据角色说明书、场景清单和最终分镜表，定义需要生成的角色设定图和主要场景设定图，并写出提示词与负向约束。
8. `image-shot-prompt-engineer`（分镜提示词工程师）：为每个 `shotKey` 写出完整图片提示词，包括角色稳定描述、构图、动作、镜头、景深、光线、场景、画风、负向约束和所需参考资产 key。
9. `image-prompt-preflight`（出图前校对）：以文本方式检查故事覆盖、一致性、16:9 构图、参考资产绑定、禁止文字、动作可视化和提示词冲突，并直接输出修正后的最终参考图与分镜图生成计划。第一版不循环回退。

九个 Agent 都使用可版本化 Prompt。禁用任一必需 Agent 时不允许创建图片批次。

## 程序步骤

九个 Agent 完成后，Java 执行以下只读规划、外部生成和本地持久化步骤：

1. **解析与校验**：每个 Agent 使用独立 JSON Schema。原始输出完整存入步骤表；只有通过 Schema 与跨步骤约束校验的数据进入下游。
2. **生成参考资产**：使用固定图片 Provider，先生成角色设定图，再生成主要场景设定图。参考图使用无文字 16:9 设定板形式，并保存 Provider、模型、提示词、尺寸、哈希与文件路径。
3. **生成分镜底图**：按 `sceneIndex + shotIndex` 顺序，每个分镜调用一次图片模型。请求包含最终提示词及该分镜声明的角色/场景参考图；不得把对白或旁白文字交给图片模型渲染。
4. **文字合成**：使用确定性排版程序生成最终图片。对话按 Agent 输出的说话角色和归一化锚点放入气泡；叙事按 1—2 句短字幕放在底部安全区。程序执行自动换行、字号下限、边界避让和对比度背景，不调用模型。
5. **交付**：所有分镜完成后状态为 `COMPLETED`。用户在图片记录中人工查看结果；第一版不写审核结论。

## 结构化合同

文本 Agent 不以自由文本互相传递关键数据。每个 Agent 的运行时协议要求输出唯一 JSON 块，后端保留原始响应并解析：

- `StoryAnalysis`：`scenes[]`、`beats[]`、`characters[]`、`locations[]`、`props[]`、`dialogues[]`、`narration[]`。
- `ContinuityBible`：`characters[]`、`props[]`、`invariants[]`、`forbiddenChanges[]`。
- `StyleBible`：`palette`、`renderingStyle`、`lighting`、`cameraRules`、`environmentRules`、`negativeRules[]`。
- `StoryboardProposal`：`shots[]`，包含 Scene、节拍、动作、人物、地点、对白、旁白和拆分理由。
- `FinalStoryboard`：稳定 `shotKey`、顺序、来源片段、画面目标、对白/字幕、说话人和文本锚点。
- `ReferencePlan`：稳定 `assetKey`、类型、目标、提示词和负向提示词。
- `ShotPromptPlan`：每个 `shotKey` 的提示词、负向提示词和 `referenceAssetKeys[]`。
- `PreflightPlan`：修正后的 `referenceAssets[]`、`shots[]` 和只用于审计的检查摘要。

后端必须拒绝重复 key、未知引用、越界图片数、漏 Scene、空提示词、图片内文字指令、无说话人的对话、字幕超长或同一镜头包含互斥动作。格式失败使当前步骤和批次失败，不使用原始报告兜底。

## Provider 能力与生成适配器

现有 `tb_ai_config.providers` 继续作为 Provider 唯一配置源，不新增或复制密钥。能力目录增加：

- `IMAGE_GENERATION`：可生成图片。
- `IMAGE_REFERENCE`：请求可携带一张或多张参考图片。

九个文本 Agent 仍只能选择启用且具备 `TEXT_GENERATION` 的 Provider。图片流程配置只能选择同时具备上述两项图片能力的固定 Provider。运行记录只保存 Provider ID、模型、请求参数和用量元数据，不保存 API Key。

新增 `AiImageGenerationService` 封装固定 Provider 的请求/响应差异，输入为文本提示词、负向提示词、16:9 参数和参考资产列表，输出为图片字节、MIME、宽高、Provider 请求 ID 和可用的计费元数据。

第一版实际适配器固定为 OpenAI Images 兼容协议：无参考图请求使用 Provider `base_url` 下的 `/images/generations`，参考图请求使用 `/images/edits` 的 multipart 多图输入；响应支持 `b64_json`，不接受任意外部文件路径。图片工作台只允许选择明确声明两项图片能力的 Provider，因此现有仅含 `TEXT_GENERATION` 的 Antigravity Provider 不会被误选。具体图片模型名与密钥属于运行配置，不写死在源码、规格或默认初始化中；在没有合格图片 Provider 时，配置页显示缺失状态并禁止创建批次。

## 数据模型

所有配置和元数据写入本地配置库；图片文件写入配置的本地运行目录，不以大字段写入 PostgreSQL。

| 表 | 用途 |
| --- | --- |
| `tb_image_agent_config` | 九个 Agent 的当前 Prompt、文本 Provider、Temperature、启用状态、版本和乐观锁 |
| `tb_image_agent_prompt_version` | Agent Prompt 的追加式历史快照 |
| `tb_image_flow_config` | 固定图片 Provider、16:9 参数、每 Scene 上限 5、全篇上限 20 |
| `tb_image_style_preset` | 画风预设、正向/负向约束、启用状态和乐观锁 |
| `tb_image_run` | 故事运行 ID、故事/单词/年级/画风快照、状态、数量、错误和时间 |
| `tb_image_run_step` | 九个 Agent 与程序步骤的顺序、输入、原始输出、解析输出、Provider 和 Token/耗时 |
| `tb_image_shot` | 最终分镜、来源片段、对白/旁白、提示词、引用 key、状态与顺序 |
| `tb_image_asset` | 参考图、分镜底图和文字合成图的类型、相对路径、MIME、宽高、哈希和生成元数据 |

图片资产已由后续 MinIO 设计替代本地根目录：数据库只保存经过校验的相对对象键和 SHA-256，内容接口按 asset ID 从私有 MinIO 读取，禁止客户端提交对象键。运行快照确保后续修改 Agent、画风或 Provider 不改变历史批次含义。

## HTTP API

### 配置

| 方法与路径 | 行为 |
| --- | --- |
| `GET /api/image-agents/flow` | 返回固定流程、九个 Agent、程序节点、图片配置和画风预设摘要 |
| `PUT /api/image-agents/{agentKey}` | 更新 Prompt、文本 Provider、Temperature 和启用状态，追加版本 |
| `GET /api/image-agents/{agentKey}/versions` | 倒序读取 Prompt 版本 |
| `POST /api/image-agents/{agentKey}/versions/{version}/restore` | 携带当前 `updatedAt`，恢复为新的最新版本 |
| `PUT /api/image-agents/flow/config` | 保存固定图片 Provider 与固定生成参数 |
| `GET /api/image-style-presets` | 读取全部画风预设 |
| `POST /api/image-style-presets` | 创建画风预设 |
| `PUT /api/image-style-presets/{presetId}` | 携带 `updatedAt` 更新或停用预设 |

### 运行与文件

| 方法与路径 | 行为 |
| --- | --- |
| `GET /api/image-runs/source-stories` | 返回 `finalStory` 非空、可用于出图的故事批次摘要 |
| `POST /api/image-runs` | 接收 `storyRunId + stylePresetId`，保存快照并异步执行 |
| `GET /api/image-runs` | 按创建时间倒序返回图片批次摘要 |
| `GET /api/image-runs/{runId}` | 返回 Agent 步骤、分镜、参考资产和最终图片元数据 |
| `GET /api/image-assets/{assetId}/content` | 返回受控图片内容，支持浏览器缓存 |

第一版没有删除、重跑、重绘、暂停、恢复或审核写入 API。

## 状态机与错误边界

批次状态为：

```text
QUEUED
  -> PLANNING
  -> GENERATING_REFERENCES
  -> GENERATING_SHOTS
  -> COMPOSITING
  -> COMPLETED
```

任一步骤失败进入 `FAILED`，停止后续调用，保留已完成步骤和图片供诊断。图片调用不自动重试，避免隐性重复消耗；HTTP 超时、Provider 拒绝、响应无图片、文件写入失败或结构化合同失败都使用有界错误信息，不返回密钥或完整外部响应头。

创建批次前必须校验：故事存在且 `finalStory` 非空、九个 Agent 全部启用且 Provider 有效、画风预设启用、图片 Provider 启用并支持两项图片能力、存储目录可写。运行创建后只使用快照，不再次读取故事正文或画风当前值。

执行继续使用进程内有界线程池。第一版明确不承诺应用重启后续跑；重启时未完成批次标记为 `FAILED`，已写文件保留。

## 初始化与兼容

`ImageAgentInitializer` 只创建缺失的九个 Agent 及其 v1 Prompt 版本、缺失的默认图片流程配置和缺失的内置画风预设，不覆盖用户已编辑记录。固定拓扑在代码目录中定义，前端不能增删或拖拽。

现有故事 Agent、故事运行表和历史数据不迁移、不修改。图片批次通过故事运行 ID 建立逻辑关联，但保存完整故事快照，不依赖故事记录后续状态。

## 测试与验收

### 后端

- 目录测试锁定九个 Agent、依赖关系、变量和只读程序节点。
- 初始化测试证明只补缺失配置，不覆盖现有 Prompt、版本、画风或图片 Provider。
- 配置测试覆盖 Provider 能力、乐观并发、Prompt 版本和画风预设快照。
- Schema 测试覆盖重复 key、未知引用、Scene 漏失、每 Scene 超过 5、全篇超过 20、互斥动作、文字指令和过长字幕。
- 执行测试证明 1—3、4—5 并行，6—9 有序；参考图先于分镜图；每分镜恰好一次图片调用；失败后不重试；全部原始输入输出和文件元数据可查询。
- 文件测试覆盖相对路径约束、MIME、哈希、缓存头和路径穿越拒绝。
- 文字合成使用固定测试 PNG，验证 16:9、对话气泡、底部字幕、自动换行和输出文件。
- 使用假图片 Provider 返回确定性 PNG 完成全链路集成测试，不消耗真实图片额度。

### 前端

- 一级菜单顺序为“Agent 工作台”后紧接“图片工作台”，并保留现有页面。
- 未保存 Prompt 切换 Agent、离开菜单和刷新时受到保护。
- Provider 下拉分别按文本能力和图片能力过滤，失效配置显示明确提示。
- 开始生成只列出合格故事和启用画风，显示故事快照预览并防重复提交。
- 图片记录正确轮询活动批次，联动批次、步骤、输入输出、参考图和分镜图；终态停止轮询。
- 页面不存在视觉评分、自动重绘、手工重绘、候选图或审核提交控件。
- 窄屏下配置详情、流程和画廊可用；图片大图可关闭并回到原选择。

### 真实验收

配置一个支持多参考图的真实图片 Provider 后，选择现有三年级故事运行一个完整图片批次。验收：

- 每个 Scene 有 1—5 张，全部不超过 20 张，故事动作覆盖完整。
- 至少生成角色设定图和主要场景设定图，分镜记录引用关系可见。
- 同一角色外观、服装、主要道具和画风跨图保持一致。
- 每张底图无文字；最终图中的对白气泡和底部旁白拼写正确、无遮挡和截断。
- 每个文本 Agent 的输入输出可审计，每个分镜只有一次真实图片生成调用。
