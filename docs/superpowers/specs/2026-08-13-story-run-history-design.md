# 故事运行与 Agent 输入输出记录设计

## 目标

在现有 Agent 工作台中加入正式故事运行能力，并在“质量预算”旁加入“运行记录”按钮。每次运行保存实际输入单词、最终故事，以及每次实际 Agent 调用的完整输入和输出；用户可在一个全屏页面中按批次和调用顺序查看。

## 已确认的界面

- “运行记录”打开全屏页面，不使用半屏抽屉或小弹窗。
- 顶部约四分之三为三栏：左侧批次列表，中间本批次实际执行过的 Agent，右侧当前批次的一行单词与所选 Agent 的输入/输出并排区域。
- 底部约四分之一固定展示当前批次的最终故事结果。
- 点击批次会同时切换单词、Agent 列表、默认选中的第一条步骤与最终结果。
- 批次列表只显示时间和单词数量；不突出状态、评分、Token 或耗时。
- Agent 列表按实际调用顺序展示。同一 Agent 在第二轮再次执行时新增一条记录，不覆盖第一轮；名称附“第 2 轮”等轮次信息以便区分。
- 输入、输出和最终结果均可独立滚动与复制。

## 正式运行入口

工作台页头新增“开始运行”按钮。第一版运行请求以明确单词列表为核心，同时支持：

1. 手动粘贴或输入单词；
2. 选择已配置的外部材料连接和词库名称，由后端只读随机抽取指定数量。

无论来源，创建批次时都把最终使用的单词及其已知释义保存为快照；后续运行记录不依赖外部材料库。

## 后端执行模型

新增两张本地表：

- `tb_story_run`：运行 ID、输入单词 JSON、年级、状态、最终故事、失败信息、累计 Token、开始/结束时间。
- `tb_story_run_step`：运行 ID、单调递增序号、质量轮次、Agent key/name、Prompt 版本、Provider/model、完整输入 JSON、完整输出、状态、Token 与耗时。

执行器在独立线程中运行，HTTP 创建接口立即返回批次，前端轮询批次详情。运行步骤严格追加，已经完成的记录不可被后续轮次覆盖。

第一版执行顺序固定为现有目录：

1. 用词策划；
2. 三个创意 Agent 并行；
3. 故事导演；
4. 故事作家；
5. 三位审核员并行；
6. 评分员；
7. 决策人；
8. 不通过时按决策触发定向修订，并回到审核、评分和决策。

执行器遵守 `tb_story_flow_config` 的质量轮次、局部修订和总 Token 上限；达到上限时停止，保留当时最新故事作为最终结果。Agent 运行前读取当前配置并把 Prompt 版本、Provider/model 写入步骤记录，确保以后可解释。

## 输入输出格式

传给模型的 user message 统一为 JSON，因此步骤输入保存同一份结构化 JSON。上游 Agent 输出以明确字段注入下游输入，例如 `vocabularyPlan`、`anonymousPitches`、`sceneBlueprint`、`story`、`independentReviews`、`scoreReport` 和 `decision`。前端对 JSON 做缩进展示，不隐藏或截断持久化内容。

最终故事优先从 `STORY_TEXT_BEGIN` / `STORY_TEXT_END` 标记提取；缺少标记时保留作家或修订 Agent 的完整输出，避免丢失结果。

## API

- `POST /api/story-runs`：校验单词并创建异步运行。
- `POST /api/story-runs/random-words`：从指定连接和词库只读随机抽词，只返回预览，不创建运行。
- `GET /api/story-runs`：按创建时间倒序返回批次摘要。
- `GET /api/story-runs/{runId}`：返回批次、全部步骤与最终结果。

列表接口不返回步骤完整输入输出，避免批次列表加载过重。

## 错误与安全边界

- 单词列表去空白、大小写不敏感去重，限制 1–50 个；随机抽取数量同样限制 1–50。
- 只允许查询已保存连接中的 `word_library` 和 `word`，使用参数化 SELECT，不写外部库。
- Provider 密钥只在执行时由 `AiConfigService.getProviderForExecution` 读取，不进入运行表、步骤输入输出、响应或日志。
- 单个 Agent 调用失败时保存失败步骤并结束批次；已完成步骤仍可查看。
- 同一时间只允许有限数量后台运行，使用固定大小线程池，避免无界创建线程。
- 本次不实现暂停、恢复、删除运行、流式输出或跨机器分布式队列。

## 验收

- 手动输入与教材随机抽词都能创建批次。
- 运行期间批次详情逐步出现步骤；完成后可查看最终故事。
- 运行记录全屏布局与确认草图一致，批次/Agent/输入输出/结果联动正确。
- 第二轮同一审核 Agent 产生独立步骤。
- 输入输出与数据库记录一致，密钥不出现在任何记录。
- 后端、前端全量测试和生产构建通过，并用真实本地 Provider 完成一次有界试跑。
